Qwen2.5-0.5B-Instruct: 247.565s -> 33.371s, 7.4x faster for 5+16=21 total positions. generated_ids identical (byte-for-byte), confirming the KV cache reproduces the no-cache baseline while running faster.

Measured on the same machine, same build (CMAKE_BUILD_TYPE=Release), back to back. Absolute seconds are not
comparable to the M2 evidence files (docs/evidence/m2-forward-*.txt), which were captured on different
hardware; only the no-cache-vs-cache ratio on this run is the point. The speed-up grows with sequence length
(no-cache recomputes the whole prefix every step: O(T^2) total work; the cache makes each step O(T)), so a
longer conversation benefits more than this short example shows.
