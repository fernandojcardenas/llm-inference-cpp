M8 part 3 -- the mask optimization measured. allowed_tokens() now memoizes
transitions: the matcher state at each trie node is interned and every
(state, byte) transition is computed once instead of once per node, so a
subtree reached under one state (a free-form string allows nearly the whole
vocabulary) costs a cache lookup per node instead of rebuilding the state.
allowed_tokens_direct() keeps the original per-node walk; the two produce
byte-identical masks (unit test GrammarMatch.MemoizedMaskEqualsTheDirectWalk,
plus an independent driver over the real 49k-token vocabulary under ASan+UBSan,
0 mismatches). step/advance/normalize are unchanged.

Machine: 2 vCPU Linux x86_64 sandbox. Before = commit base c585cdb's parent
state (pre-optimization); after = this change. Clean -O3 build, no sanitizers.

Reading this:
- Allocations per trie node fall from ~12-13 to ~0.25: the memo computes each
  distinct (state, byte) transition once rather than rebuilding the matcher
  State -- and its heap allocations -- at every node.
- The heavy free-form-string mask (walking ~99,500 nodes) drops from 50-63 ms
  to 6-9 ms; the word-list GBNF, heavy at every position, from ~6.5 ms to
  ~0.45 ms. The remaining cost is the trie traversal itself (visiting the nodes
  and writing the mask bits), not allocation.
- End to end on SmolLM2-135M-Instruct over the five schemas (tools/
  bench_decode_overhead.py), the full mask a sampled token pays drops from
  12.17 ms to 1.70 ms, so constrained sampling now adds 2.5% over forward+
  sampling instead of 19%; constrained greedy stays nearly free (0.8% -> 0.3%).
- Masks are unchanged: every token the grammar allowed before, it allows now
  (the equivalence test and the real-model constrained-JSON eval, which still
  reports ALL CONSTRAINED OUTPUTS VALID, confirm it).
